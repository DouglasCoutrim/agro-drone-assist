# Decisões técnicas

- Use one shared partner form for organization-scoped suppliers and carriers, with counted server pagination and role-protected writes, to keep both registers consistent and isolated.
- PremiumTable paginates record lists by default; external pagination supplies server totals and nested item editors may disable it, so records remain reachable without rendering every row.
- Desktop and mobile navigation share NavModules and navConfig, so module grouping and destination availability stay synchronized.
- Load external fonts through a document-head link rather than CSS imports, so CSS compilation never resolves remote font URLs as local files.
- Sale creation follows router navigation and resets the form on every navigation entry; closing returns to the sale list so repeated menu clicks cannot reuse an edited sale.
- Guard quote-to-OS conversion with the shared canConvertOrcamento predicate in both the action and UI, because combined quotes already represent existing service orders.
- Shared dialogs provide mobile padding and vertical scrolling by default; callers with dedicated scroll bodies may override these defaults explicitly.

- Logos das empresas ficam no bucket público `logos`, em pastas identificadas pela organização; leitura pública serve telas e PDFs, enquanto gravação é restrita ao administrador da própria organização.
- No estoque, `custo_unitario` e `preco_venda` são entradas independentes; importações não devem calcular margem automaticamente para preservar o preço escolhido pelo usuário.
- A instalação na tela inicial usa somente manifestos e ícones; não gerar nem registrar Service Worker de cache, e manter `/sw.js` temporariamente apenas como encerramento do Workbox antigo.
- Build da aplicação deve preferir variáveis públicas gerenciadas de conexão e fornecer fallback público específico do projeto via configuração do Vite, porque a publicação pode omitir `.env` e deixar a tela vazia.
- Keep assistant assignments, commissions, and internal OS notes in staff-only views; customer-facing PDF and messages must use explicit customer-facing fields, because internal compensation must not leak to clients.
- Ao editar uma OS, preservar o orçamento sem lançamentos detalhados e atualizar os itens por identidade, confirmando exclusões antes de salvar; substituir toda a lista apaga lançamentos quando uma leitura falha.
- Autorizar edição de comissões pelo papel `admin` somente para perfis com papel `tecnico` da mesma organização, mesmo quando um usuário acumula os dois papéis; a verificação deve ficar no banco para impedir contorno pela interface.- Peças lançadas em OS/orçamento vêm de `itens_estoque` (gravadas em `itens_os.item_estoque_id`); `produto_id` fica só para lançamentos legados, porque o catálogo `produtos` não reflete o estoque.

- Retired assistant and tax-retention screens must not perform background reads or replace historical assignments during OS edits; retain stored historical tables and commission RPCs until a separate data-aware retirement is approved.
- Team management belongs to Equipe; Configuracoes keeps personal profile, password and organization segments without duplicate member queries or non-persistent notification controls.
- Keep redirects for retired product and retention pages so existing bookmarks resolve to supported screens.

- Technician financial summary and statement read principal commission_total from ordens_servico, not retired os_technicians/retention ledgers, so new OS commissions remain visible without assistant assignments.
- Tailwind configuration must use global CSS theme tokens and native scales, never import the retired design-system module, so stylesheet compilation remains independent of removed application files.

- Web push uses a dedicated /push-sw.js worker scoped to /push/ (no caching) and a notifications INSERT trigger that calls send-web-push, which re-reads the notification server-side and only sends recent ones, so the public trigger call cannot be abused to spoof messages.
- Purchase orders (pedidos_compra) group solicitacoes_compra items by sector; items remain the unit for supplier quotations, so only pending items are editable.
- Purchase-order drafts store a base revision and restore only against fresh matching server data; saves recheck that revision and scope item mutations to pending rows, so stale drafts cannot replace current quotations or new items.
- Received-invoice actions decode handled HTTP error response bodies before showing a fallback, so configuration and provider guidance reach the user.
- Stock product photos store only an external URL (itens_estoque.imagem_url) found via the buscar-imagem-produto function (Firecrawl image search), so images are not kept in Storage.
- Tool depreciation is computed client-side from purchase value, purchase date, useful life and residual percentage (src/lib/depreciacao.ts), so the reimbursement value is always current without scheduled jobs; non-admins only read tools assigned to themselves via RLS.
- User access is a list of blocked menu hrefs (user_permissions.rotas_bloqueadas) checked against navConfig by menu and ProtectedRoute, so new menu items are allowed by default and the permission screen always mirrors the menu; acesso_* columns are legacy.
- Per-item discount: the admin sets `desconto_maximo_percentual` on itens_estoque/servicos; the buyer enters a percentage that is converted to R$ and clamped to that cap (src/lib/desconto.ts) in orçamentos/OS (OSItemsSection) and vendas. OS items snapshot the cap in itens_os so the limit survives reloads.
- Fechamento do dia: `resumo_vendas_dia(date)` (SECURITY INVOKER, org-scoped) returns the day's totals and `por_forma`; `fechamentos_dia` stores one row per (organization_id, data) with the summary plus optional `dinheiro_contado`/`observacao`, written by any authenticated member of the org (no admin-only restriction). UI lives in `src/components/relatorios/FechamentoDia.tsx`, rendered inside Relatórios and independent of its `periodo`/`loading` gate.
- RLS helpers live in the `private` schema (`private.get_user_org_id`/`has_role`/`is_admin_or_tecnico`/`is_platform_admin`/`get_user_role`/`set_user_roles`), with SECURITY INVOKER wrappers in `public`. If `private` is missing, every org-scoped policy fails with `schema "private" does not exist`; restore it from `supabase/migrations/20260921160017_*` + `20260922131115_*` + `20260922131134_*`.
- Fiscal operations live in separate /fiscal/* screens sharing src/components/fiscal/fiscalShared.tsx; sale-return notes keep venda_id empty and link via nota_origem_id, because the Focus webhook writes the note number onto the sale whenever venda_id is set.
- Sales may mix services and parts; service lines use produto_id null + ncm '00' (src/lib/venda-servico.ts), and NF-e is blocked for them in PDV, NfeVenda and emitir-nfe-venda, because SEFAZ NF-e only accepts goods.
- `itens_estoque.finalidade` (`revenda` | `uso_interno` | `ferramenta`) separa o que é vendável do que é consumo/patrimônio. Toda busca de venda (OS, orçamento, PDV, vendas, autocomplete de catálogo) filtra `finalidade = 'revenda'`; a tela de Estoque lista tudo e filtra por finalidade.
- Ferramenta da loja não é duplicada em `patrimonio_ferramentas`: fica em `itens_estoque` com `finalidade = 'ferramenta'` e circula pelas RPCs `transferir_estoque_tecnico` / `devolver_estoque_central` (loja → estoque do técnico → loja). `patrimonio_ferramentas` continua sendo o ativo com depreciação.
- A numeração de OS é única por organização (`ordens_servico_org_numero_key`); `generate_os_number()` ignora números fora do padrão `OS-###`, então não reaproveita sufixo de outra empresa.
- A marca LivreOS (ícone + "LivreOS" + "Enterprise") é renderizada por `src/components/brand/LivreOSLogo.tsx`, com o ícone em `src/assets/logo-icon.png` e variantes `tone="onDark" | "onLight"`; telas não devem recriar esse lockup nem importar o ícone direto, para a identidade ficar idêntica na sidebar, no cabeçalho mobile, no login, no portal admin e na landing.
- O ícone da marca ocupa ~1,3x a altura do bloco de texto (proporção do modelo oficial) e o componente recorta a moldura vazia do arquivo em canvas no primeiro uso, tornando o fundo branco transparente; assim qualquer export do emblema preenche o mesmo espaço em fundo claro ou escuro sem depender de recorte manual do arquivo.
- O catálogo legado `produtos` está congelado: nenhuma tela lê ou grava nele. Produtos, peças e ferramentas vivem em `itens_estoque`.
- Seletor de técnico usa papéis `tecnico` ou `admin` (admins também atendem OS) e carrega `profiles.nivel_tecnico`; papéis apenas `consulta` nunca são atribuídos como responsáveis técnicos.
- Peça não pode virar serviço: `Servicos` e `ServicoDialog` recusam cadastro cuja descrição já exista em `itens_estoque` da mesma organização.
- Triggers de estoque baixo (`trg_estoque_baixo_solicitacao`/`trg_notify_estoque_baixo`) só agem na transição acima→abaixo do mínimo, para não criar solicitação/notificação por produto recém-cadastrado.
- Datas sem hora (colunas `date` e `<input type="date">`) nunca passam por `new Date()` nem `toISOString()`: usar `todayDateInput`, `parseDate`, `formatDate` e `dateOnlyToIso` de `src/lib/formatters.ts`. O parse UTC do JS desloca o dia em fusos como UTC-3 (ex.: `new Date("2026-11-11").toLocaleDateString('pt-BR')` mostrava 10/11/2026). Para colunas `timestamptz` que guardam apenas uma data (ex.: `ordens_servico.data_previsao`, `technician_expenses.expense_date`) gravar via `dateOnlyToIso` (meio-dia local).
- Gravacao de venda e estoque migrou para o banco: `criar_venda(_payload jsonb)` cuida de numeracao por organizacao, preco/teto vindos de `itens_estoque` ou `servicos`, totais e baixa de estoque na mesma transacao; `ajustar_estoque(_item_id,_delta,_motivo,_origem_tipo,_origem_id)` soma o delta e registra `movimentacoes_estoque`. O front (`useVendasData`) envia so as escolhas do operador e o preco do navegador e ignorado, por isso PDV e Vendas exibem o preco do cadastro como somente leitura. Linhas de servico usam `servico_id` (preco = GREATEST(preco, valor_fixo, valor_hora)) e item livre usa `produto_id` nulo; nenhum dos dois movimenta estoque. `criar_venda` tambem grava `vendas.nfe_dados` e `vendas.ambiente`, que a emissao de NF-e le. `desconto_maximo_percentual = 0` significa sem teto (ate 100), igual a `src/lib/desconto.ts`, e o banco precisa espelhar isso senao bloqueia descontos de itens sem teto configurado.
- Teto de desconto por item tem uma regra unica no sistema: 0 (nao configurado) vai ate o teto absoluto de 100 e um valor maior que 0 limita naquele percentual. Ela vive em `src/lib/desconto.ts` (tetoDesconto), em `venda_linha_calcular` (vendas) e em `enforce_itens_os_price` (OS); mexer em uma sem as outras faz o mesmo item aceitar 100 num lugar e 0 no outro.
- `venda_linha_calcular(_organization_id, _linha)` e a regra unica de linha de venda (produto de estoque, servico ou item livre): preco, teto de desconto e dados fiscais vem do catalogo, item de estoque exige quantidade inteira e so ele movimenta estoque. `criar_venda` e `editar_venda` usam essa funcao; qualquer caminho novo de venda deve chamar a mesma funcao em vez de repetir a regra.
- Edicao e cancelamento de venda sao RPCs (`editar_venda`, `cancelar_venda`); o hook apenas as chama e recarrega a venda. Edicao reconcilia estoque por diferenca (um movimento por item alterado) e campo ausente no payload fica como estava; cancelamento e idempotente e falha na segunda chamada em vez de devolver o estoque duas vezes.
- Estoque nao guarda fracao: `ajustar_estoque` recusa delta fracionado e a venda recusa quantidade fracionada em item de catalogo (linhas de servico e item livre seguem aceitando fracao). Telas que escrevem estoque devem fornecer inteiros.
- PENDENTE DE DECISAO: `enforce_itens_os_price` retorna `NEW` sem travas quando `auth.uid()` e nulo ou o usuario e admin, entao administradores ainda podem gravar preco e desconto livres em itens de OS, enquanto as RPCs de venda aplicam preco de catalogo para todos. Unificar exige escolher entre 'admin tambem segue o catalogo' e 'admin pode sobrescrever'.
- Relatorio personalizado nao aceita identificador vindo do navegador: `relatorio_fontes` guarda o catalogo (tabela, colunas com rotulo/tipo, filtros permitidos, coluna de data e perfis) e `gerar_relatorio` confere cada chave contra ele antes de montar o SQL (`format('%I')` para identificador, `format('%L')` para valor), filtra sempre por `get_user_org_id(auth.uid())` e e SECURITY INVOKER para o RLS da origem valer junto. Fonte nova de relatorio e linha no catalogo, nao codigo novo na tela.
- No relatorio personalizado, periodo em coluna com hora usa o fuso da empresa (`business_tz()`) e o total vem de `count(*) over()` antes do limite, entao `limitado` mostra que a tela ve so parte dos registros. Fonte inexistente e fonte sem permissao devolvem a MESMA mensagem ("Acesso negado a esta fonte"), senao a diferenca revela o catalogo a quem nao pode ver.
- Relatorio em PDF sai pelo gerador padrao (`gerarDocumentoPadrao`) com `orientacao: 'paisagem'` e `tabela.ajustarLargura: true`. Nesse modo a largura e MEDIDA com `getTextWidth`, nunca estimada por quantidade de caracteres: o minimo de cada coluna e o maior pedaco que nao pode ser quebrado, e em coluna alinhada a direita (valor, data, quantidade) o pedaco e o valor inteiro, senao "R$ 3.049,44" sai partido em duas linhas. A sobra vai para quem tem texto longo e, se nao couber, o corpo da tabela cai de 8,5 ate 6 antes de aceitar quebra. Retrato fica reservado para documento de uma parte so (recibo, orcamento, OS); tabela larga em retrato nao e legivel. O relatorio personalizado abre com poucas colunas (os campos principais da fonte) porque marcar todas de uma vez nao cabe legivel em A4.
- Auditoria de dados: `public.audit_trail` guarda uma linha por alteracao (INSERT/UPDATE/DELETE) com SOMENTE os campos que mudaram, antes e depois, quem fez (nome e e-mail copiados no momento, para a trilha nao depender de o usuario existir depois) e qual registro. Quem escreve e `public.audit_row()`, gatilho SECURITY DEFINER `trg_audit` aplicado por tabela -- o usuario nao tem, nem deve ter, permissao de escrita na trilha. Ela e append-only de proposito: nao existe policy de UPDATE nem de DELETE, entao nem o admin reescreve ou apaga o que foi gravado. Leitura: admin da propria organizacao (`organization_id = get_user_org_id(auth.uid())` somado a RLS) e platform admin. Tela em `/auditoria`, no menu Configuracoes.
- Trilha: credencial (senha/token/chave/secret/certificado/XML/payload/asaas) entra como `***`, CPF/CNPJ entra mascarado (3 primeiros + 2 ultimos caracteres) e texto acima de 300 caracteres e cortado. `updated_at` sozinho nao gera linha, para um UPDATE que nao muda nada de fato nao poluir a trilha. Tabela nova de negocio so passa a ser auditada se for incluida na lista do `foreach` da migration `20261003200000_auditoria_trilha.sql`; tabela sem `organization_id` precisa de derivacao (venda_itens herda a organizacao da venda dona da linha). Fora da trilha por serem ruido: notifications, os_historico, sincronizacao_nfe_recebidas, admin_audit_log, nfe_config_backup_20261111, support_tickets e tenant_invoices.
- Auditoria em PDF: sai pela propria tela `/auditoria` com `gerarDocumentoPadrao` em paisagem e colunas de largura FIXA (sem `ajustarLargura`), porque as seis colunas sao conhecidas e o id do registro precisa de espaco garantido -- um valor longo sem espacos (json, url) deformaria a medicao automatica e encolheria as outras colunas. Lista, CSV e PDF passam pelo mesmo `aplicarFiltros`, entao o arquivo exportado e o recorte que esta na tela, e a observacao do PDF repete esses filtros. Cada linha traz "campo: antes -> depois" e alteracoes com mais de 500 caracteres aparecem resumidas no PDF; o CSV traz o conteudo completo.
- REGRA DO SISTEMA: todo campo de valor financeiro aparece com R$ em tela, CSV e PDF, sempre pelo `formatCurrency` de `src/lib/formatters.ts`. Quantidade, contagem, percentual e nota nunca levam R$. No relatorio personalizado a distincao vem do catalogo: coluna de dinheiro e tipo `moeda` e quantidade e tipo `numero`, e o tipo manda na formatacao (tela, CSV e PDF) e tambem na comparacao do filtro (os dois comparam como numero). Coluna nova de dinheiro no catalogo que ficar como `numero` aparece sem R$.
